금융 시뮬레이터 프로젝트에서 코드 리뷰에 AI를 붙였다. 
GitHub Actions에 [claude-code-action](https://github.com/anthropics/claude-code-action)을 연결해서

- PR이 열리거나 push되면 Claude가 **자동으로 리뷰**하고,
- PR 코멘트에 `@claude`를 언급하면 **질문에 답하게** 했다.

그런데 이 자동 리뷰가 **3개월 동안 단 한 번도 코멘트를 남기지 않았다.** 체크는 매번 초록불이었다.
원인은 결국 하나였는데, 거기까지 가는 동안 헤맸다. 그 과정을 정리해 둔다.

---

## 🚨 초록불인데 아무 일도 없다

---

```yaml
# .github/workflows/claude-code-review.yml (처음 버전)
on:
  pull_request:
    types: [opened, synchronize, ready_for_review, reopened]

jobs:
  claude-review:
    steps:
      - uses: anthropics/claude-code-action@v1
        with:
          claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
          plugin_marketplaces: 'https://github.com/anthropics/claude-code.git'
          plugins: 'code-review@claude-code-plugins'
          prompt: '/code-review:code-review ${{ github.repository }}/pull/${{ github.event.pull_request.number }}'
```

PR을 올리면 `claude-review` 체크가 돌고, 1분 안팎에 `success`로 끝난다. 그런데 PR 어디에도 리뷰 코멘트가 없다.
![`claude-review` 액션 성공 이미지](https://mcawm4stpvqmonk2.public.blob.vercel-storage.com/claude-code-review/reviewCheckSuccess.png)

### 왜 3개월 동안 몰랐나

- 체크가 실패하지 않았다. 실패 알림이 없으니 아무도 로그를 열어 보지 않았다.
- "AI 리뷰가 원래 멘션했을때만 달리는 건가?" 하고 넘겼다. 기대한 결과가 **없는 것**은 에러가 **있는 것**보다 눈에 띄지 않았다.

---

## 1차 시도. 자동 실행 모드에서는 Bash가 막혀 있다?

---

claude-code-action은 두 가지 모드로 돈다.

| 모드 | 언제 | 코멘트 게시 |
|---|---|---|
| 태그 모드 | `@claude` 멘션에 반응 | 액션이 대신 게시 |
| 자동 실행(agent) 모드 | `prompt`를 직접 지정 | Claude가 직접 게시 필요 |

리뷰 워크플로는 `prompt`를 지정했으니 **자동 실행 모드**다. 그래서 Claude가 직접 `gh pr comment`로 PR에 코멘트를 달아야 한다.
그런데 처음 워크플로에는 `claude_args`가 없어서 Claude에게 `gh`를 실행할 권한이 없다고 판단했다.

`claude_args`로 리뷰에 필요한 `gh` 명령만 허용했다. (다음엔 과정을 볼 수 있게 `show_full_output`도 함께 켰다.)

```yaml
claude_args: |
  --allowedTools "Bash(gh pr view:*),Bash(gh pr diff:*),Bash(gh pr comment:*),..."
show_full_output: true # 원인 확인용, 나중에 제거
```

나중에 알고 보니 이게 처음부터 원인이었는지는 확실하지 않다. `code-review` 플러그인의 명령 파일에는 필요한 권한이 이미 선언돼 있었다.

```yaml
# anthropics/claude-code — plugins/code-review/commands/code-review.md
allowed-tools: Bash(gh pr comment:*), Bash(gh pr diff:*), Bash(gh pr view:*), ...
```

플러그인을 쓰는 동안에는 이 설정으로 `gh` 권한이 열려 있었을 수 있다. 수정 전 로그에도 권한 거부는 0건이었다.

그래도 `--allowedTools`는 결국 필요한 설정이 됐다. 2차 시도에서 플러그인을 빼고 `prompt`에 지시를 직접 쓰게 되면서, 권한을 열어 줄 플러그인이 없어졌기 때문이다.

### ➕ `@claude` 중복 응답

GitHub에서는 PR 코멘트도 `issue_comment` 이벤트다. 
이슈용 워크플로(`claude-issue-comment.yml`)에 이슈/PR 구분 조건이 없어서, PR 코멘트에도 PR용 워크플로(`claude.yml`)와 함께 반응하고 있었다.

```yaml
# claude-issue-comment.yml — 이슈 코멘트만 처리
if: github.event.issue.pull_request == null

# claude.yml — PR 코멘트만 처리
if: github.event_name == 'issue_comment' && github.event.issue.pull_request && contains(github.event.comment.body, '@claude')
```

이걸로 해결될 줄 알았다.

## 2차 시도. 리뷰어가 결과를 기다리지 않고 퇴근한다

---

권한을 열고 새 PR을 올렸다. 체크는 또 `success`, 코멘트는 또 없다.

이번엔 `show_full_output` 덕분에 로그가 보였다. 권한 거부는 0건이었다.

![show_full_output 로그](https://mcawm4stpvqmonk2.public.blob.vercel-storage.com/claude-code-review/backgroundAgentsLog.png)

```
"permission_denials": [],
"result": "Both agents are running in the background. I'll wait for their results before going further.",
...
No buffered inline comments
```

`code-review` 플러그인은 리뷰 전에 사전 점검(PR 상태 확인, `CLAUDE.md` 찾기)을 **서브에이전트 2개에 백그라운드로** 맡겼다. 메인 세션은 "결과 기다릴게"라고 답했다. 도구 호출 없이 텍스트로만 답했으니 이 답이 곧 최종 `result`가 되고, 세션은 그대로 끝났다.
GitHub Actions에서는 세션이 끝나면 `claude` 프로세스를 종료하기 때문에, 서브에이전트도 함께 사라졌다. 실제 리뷰를 할 에이전트는 띄워 보지도 못했다.

플러그인을 빼고, claude-code-action 공식 예제([pr-review-comprehensive.yml](https://github.com/anthropics/claude-code-action/blob/main/examples/pr-review-comprehensive.yml)) 방식대로 `prompt`에 리뷰 지시를 직접 썼다.

```yaml
prompt: |
  REPO: ${{ github.repository }}
  PR NUMBER: ${{ github.event.pull_request.number }}

  이 PR을 리뷰하고 결과를 PR에 게시해줘. 모든 코멘트는 한국어로 작성해.

  - `gh pr view`, `gh pr diff`로 변경 내용을 확인하고, 필요하면 저장소 파일을 직접 읽어 맥락을 파악해.
  - 버그, 보안 문제, 엣지 케이스 누락, 테스트 누락 등 실제로 문제가 되는 것 위주로 지적해. 스타일 취향 지적은 하지 마.
  - 서브에이전트나 백그라운드 작업을 쓰지 말고 직접 리뷰를 끝낸 뒤 게시해.
  - 특정 코드 줄에 대한 지적은 `mcp__github_inline_comment__create_inline_comment`로 인라인 코멘트를 남겨.
  - 마지막에 `gh pr comment`로 전체 요약 코멘트를 하나 남겨. 문제가 없으면 문제없다고 짧게 남겨.
claude_args: |
  --allowedTools "mcp__github_inline_comment__create_inline_comment,Bash(gh pr view:*),Bash(gh pr diff:*),Bash(gh pr comment:*)"
```

`--allowedTools`도 실제로 쓰는 도구만 남기고 줄였다.

## 3차 시도. 워크플로를 고친 PR에서는 리뷰가 아예 안 돈다

---

수정을 머지하고, 확인 겸 `show_full_output`을 지우는 PR을 올렸다. 체크는 `success`인데 **11초** 만에 끝났다. 리뷰를 했다기엔 너무 빠르다.

![workflow validation 경고 로그](https://mcawm4stpvqmonk2.public.blob.vercel-storage.com/claude-code-review/workflowValidationSkipped.png)

claude-code-action은 **PR의 워크플로 파일이 main과 똑같을 때만** 실행된다. PR에서 워크플로를 바꿔 Claude에게 엉뚱한 일을 시키지 못하게 막는 보안 장치로 보인다. 그리고 건너뛸 때도 체크는 `success`로 끝난다.

확인용으로 고른 PR이 하필 리뷰 워크플로 파일을 고치는 PR이었던 것이다. 그래서 워크플로 파일은 건드리지 않고 **빈 커밋 하나만 있는 검증용 PR**을 따로 올렸다.

```bash
git commit --allow-empty -m "test: Claude 자동 리뷰 게시 확인용 빈 커밋 (#53)"
```

1분 뒤, 드디어 첫 코멘트가 달렸다.

> 리뷰 결과: 이 PR은 변경된 파일이 없는 빈 커밋입니다(additions 0, deletions 0). 검토할 코드가 없어 버그, 보안, 엣지 케이스, 테스트 관련 지적 사항도 없습니다. (...) 머지 금지 표시가 있으니 확인 후 닫으시면 됩니다.

3개월 만에 들은 첫마디가 "검토할 게 없다"였지만, 그래도 반가웠다.

---

## 결론

- **`success`는 "에러 없이 끝났다"는 뜻이지 "원하는 일을 했다"는 뜻이 아니다.** 세 번 모두 체크는 초록불이었다. 결과(여기선 코멘트)가 실제로 생겼는지를 확인해야 한다.
- **로그를 볼 수 있게 만드는 게 먼저다.** `show_full_output`을 켜고 나서야 진짜 원인이 보였다. 로그 없이 추측만으로는 원인을 찾기 어렵다.
- **AI 에이전트도 실행 환경의 수명을 따른다.** 백그라운드 작업은 로컬에선 자연스럽지만, CI에서는 세션이 끝나는 순간 같이 사라진다.
- **워크플로 변경은 main에 머지한 뒤, 그 파일을 건드리지 않는 PR에서 확인한다.**
